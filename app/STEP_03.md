# Шаг 3. Список и карточка заявок (полнофункциональный UI)

## Что появилось

### Новые модули Python
- **`core/permissions.py`** — RBAC: функции `can_create_request`,
  `can_edit_request`, `can_view_request`, `visible_requests_qs`,
  `can_transition`, `allowed_transitions_for`. Машина состояний жизненного
  цикла заявки (`ALLOWED_TRANSITIONS`).
- **`core/services.py`** — сервисный слой: `generate_request_number`
  (формат `REQ-YYYY-NNNNNN`), `create_request`, `transition_request`
  (с записью в `StatusHistory` и `AuditLog`), `add_comment`.
- **`core/forms.py`** — `RequestForm` (с **динамическими low-code-полями**!),
  `CommentForm`, `RequestFilterForm`.
- **`core/templatetags/core_tags.py`** — фильтры `status_color`,
  `status_icon`, `priority_color` для красивых бейджей.

### Новые маршруты
- `/requests/` — список с фильтрами и пагинацией;
- `/requests/new/` — создание;
- `/requests/REQ-XXXX-XXXXXX/` — карточка;
- `/requests/.../edit/` — редактирование;
- `/requests/.../transition/<status>/` — смена статуса (POST);
- `/requests/.../comment/` — добавление комментария (POST).

### Новые шаблоны
- `core/request_list.html` — таблица заявок, фильтры, пагинация.
- `core/request_detail.html` — карточка: описание, low-code-поля,
  история статусов, комментарии с формой добавления, кнопки переходов.
- `core/request_form.html` — общая форма создания/редактирования
  с автоматическим выводом cf_*-полей low-code-конструктора.

### Обновлены
- `core/views.py` — все новые views.
- `core/urls.py` — все новые маршруты.
- `templates/base.html` — пункт «Заявки» в шапке стал активной ссылкой,
  с подсветкой active при нахождении на разделе.
- `core/templates/core/home.html` — кнопка «Все заявки», ссылки в блоке
  «мои заявки».

## Применение

```powershell
git pull
# моделей не меняли — миграции не нужны
python manage.py runserver
```

## Что проверить

### Под `executor1` / `demo1234`
1. После входа в шапке появилась кнопка «Заявки» — кликаем.
2. Видны только **3 заявки**, где executor1 — исполнитель (фильтрация по роли).
3. Кнопки «Новая заявка» **нет** (исполнитель не может создавать).
4. Открываем «Перенастроить почтовый клиент» — видим:
   - бейдж статуса «В работе» (синий) и приоритета «Средний»;
   - доступные переходы: «На проверке», «Приостановить», «Отменить»;
   - **кнопка «Закрыть» отсутствует** — это привилегия менеджера;
   - кнопка «Редактировать» **отсутствует** — исполнитель не правит карточку.
5. Жмём «Перевести в На проверке» — статус меняется, в истории появляется
   запись, заявка остаётся в списке.
6. Оставляем комментарий через форму внизу — появится в списке выше формы.

### Под `manager` / `demo1234`
1. Видны **все 14 заявок**.
2. Есть кнопка «Новая заявка» в списке.
3. На карточке любой заявки в `review`-статусе доступна кнопка
   «Перевести в Выполнена» — нажмите, заявка закрывается.
4. Открываем заявку «Не подключается VPN»: правее «Описания» — блок
   «Дополнительные сведения» с полями `Срочность по мнению клиента`
   и `Готов оплатить срочный выезд` — это работа low-code.

### Под `operator` / `demo1234`
1. Тоже видит всё. Создаёт новую заявку — нажимаем «Новая заявка».
2. В форме видны и обычные поля, и **3 кастомных** (low-code):
   `Серийный номер устройства`, `Срочность по мнению клиента`,
   `Готов оплатить срочный выезд`.
3. Заполняем, отправляем — попадаем на карточку только что созданной
   заявки с автоматически сгенерированным номером `REQ-2026-NNNNNN`,
   статусом «Новая», и заполненными low-code-полями.
4. На карточке — у оператора есть «Перевести в В работе», но нет
   «Перевести в Выполнена» (это только менеджер).

### Фильтры в списке
- Поиск по «vpn» — найдётся одна заявка про VPN.
- Фильтр по статусу «В работе» — показывает только in_progress.
- Галка «Только открытые» — скрывает done и cancelled.
- Сброс фильтров — кнопка «Сброс» рядом с «Применить».
