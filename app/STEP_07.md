# Шаг 7. XLSX-экспорт, журнал действий, графики SLA с drill-down

К моменту начала этого шага у нас уже работает Шаг 6 (автотесты).
Теперь добавляем три последние функциональные улучшения, закрывающие
«хотелки» из плана:

- **B.** Графики на странице SLA + drill-down (клик по графику → список заявок);
- **C.** Экспорт отчётов в XLSX (Excel) через `openpyxl`;
- **D.** Страница «Журнал действий» (AuditLog) в основном интерфейсе.

## Шаг 7.2. Что проверить

### B. Графики SLA + drill-down

1. Зайти под `manager` (пароль `demo1234`).
2. Перейти в **Отчёты → Соблюдение SLA**.
3. На странице должны быть:
   - **Doughnut-график** «Общий SLA» (зелёный = в срок, красный = просрочено).
   - **Stacked bar-chart** по приоритетам.
   - Под графиками — таблица с бейджами.
4. **Drill-down:** кликнуть по столбцу bar-chart → должен перейти на
   `/requests/?priority=<id>` (список заявок этого приоритета).
5. Кликнуть по строке таблицы → то же самое.
6. Проверить by_period: перейти в **Отчёты → Динамика по периоду**,
   кликнуть по столбцу дня → `/requests/?date_from=...&date_to=...`.

### C. XLSX-экспорт

7. На каждой странице отчётов появились **две кнопки**: «CSV» (серая) и
   «Excel» (зелёная).
8. Скачать Excel-файл на любом отчёте → открыть в Excel / LibreOffice.
   Должна быть таблица с заголовками, шириной колонок и строкой итогов.

### D. Журнал действий

9. В шапке у менеджера/админа появился пункт **«Журнал»** (иконка часов).
10. На странице `/audit/` — таблица всех действий с цветными бейджами:
    - зелёный «Создание», синий «Статус», серый «Комментарий» и т. д.
11. Фильтры: действие, сущность, автор, текстовый поиск.
12. Пагинация по 50 записей.

## Шаг 7.4. Архитектурные заметки (для ВКР)

В тексте ВКР можно отразить:

1. **Экспорт XLSX** — отдельный модуль `export_xlsx.py` с тремя
   функциями. Используется библиотека `openpyxl` (MIT-лицензия).
   Формирование файла происходит в памяти (`BytesIO`), без временных
   файлов на диске — это безопасно при конкурентных запросах.

2. **Drill-down** — реализован исключительно на клиенте (JavaScript,
   Chart.js `onClick`), без дополнительных API-эндпоинтов. Это
   упрощает серверную часть и не требует AJAX.

3. **Журнал аудита** — уже существовавшая модель `AuditLog` теперь
   доступна из основного UI (ранее — только через `/admin/`). Это
   демонстрирует принцип *«данные создаются один раз — потребляются
   в нескольких местах»*.
