# Шаг 5. Раздел «Клиенты»

Последний крупный «фронтовой» раздел системы.

## Что появилось

### Маршруты
- `/clients/` — список с поиском и пагинацией;
- `/clients/new/` — создание;
- `/clients/<id>/` — карточка клиента с историей его заявок;
- `/clients/<id>/edit/` — редактирование.

### Файлы
- `core/permissions.py` — `can_view_clients` и `can_edit_client`.
- `core/forms.py` — `ClientForm`, `ClientFilterForm`.
- `core/views.py` — 4 новые view: `client_list`, `client_detail`,
  `client_create`, `client_edit`. Плюс `request_create` теперь
  принимает `?client=<id>` для предзаполнения.
- `core/templates/core/client_list.html` — таблица со счётчиками заявок,
  кликабельные телефон и email.
- `core/templates/core/client_detail.html` — карточка с двумя колонками:
  контакты + история заявок этого клиента.
- `core/templates/core/client_form.html` — форма создания/редактирования.

### Связи между разделами
- В шапке пункт «Клиенты» стал **активной ссылкой**.
- На карточке заявки имя клиента **кликабельно** — ведёт в карточку клиента.
- На карточке клиента кнопка **«Создать заявку»** ведёт в форму
  создания заявки с уже выбранным клиентом.

## Применение

```powershell
git pull
python manage.py runserver
```

Миграций нет.

## Что проверить

### Под `manager` или `operator`
1. В шапке появилась активная ссылка **«Клиенты»**. Кликаем — таблица
   из 5 клиентов с количеством заявок у каждого.
2. Поиск: введите «техно» — найдётся ООО «ТехноСервис».
3. Открываете «ООО «Ромашка»»:
   - Слева — контакты (с кликабельными телефоном и email).
   - 3 карточки сводки: всего заявок / открытых / закрытых.
   - Справа — история заявок этого клиента (Не работает интернет,
     Перенастроить почтовый клиент, Подключить нового сотрудника).
4. Жмёте **«Создать заявку»** — попадаете в форму создания, и клиент
   уже подставлен.
5. Жмёте **«Редактировать»** — меняете контактное лицо, сохраняете.

### Под `executor1`
1. В шапке тоже видна ссылка **«Клиенты»**.
2. Список клиентов виден.
3. Открываете карточку клиента — **кнопок «Редактировать» и «Создать
   заявку» нет** (это правильно: исполнитель не управляет клиентами).
4. История заявок показывает **только заявки, где executor1 — исполнитель**
   (фильтрация через `visible_requests_qs`). Это критично для RBAC.
5. На карточке заявки имя клиента — кликабельная ссылка, переход
   работает.
